The Problem

NISRA provides recreation programs for individuals with disabilities, but their website failed basic accessibility standards. Small text, poor contrast, and unclear forms prevented visually impaired users from registering independently — creating barriers that directly contradicted NISRA's mission of inclusion.

"How might we improve website accessibility so users with visual impairments can read content, navigate pages, and complete tasks without frustration or assistance?"

Key Accessibility Challenges

1
Small Text Size
Users with low vision couldn't read program details or form fields, requiring assistance to navigate basic tasks.
2
Poor Color Contrast
Text blended into backgrounds, failing WCAG standards (below 4.5:1 ratio). Users described it as "straining to read."
3
Unclear Form Labels & Missing Alternative Text
Sign-up fields lacked descriptive labels and images had no alt text, making the site effectively unusable for screen reader users.

Key Insights from Interviews

1
Text was unreadable

Small font sizes and low contrast made content inaccessible. Participants reported needing someone else to read the screen for them.

2
Forms were confusing and incomplete

Missing and vague form labels caused errors and abandonment. Screen readers couldn't interpret the fields, leaving assistive technology users with no guidance.

3
Loss of independence and confidence

Users consistently needed caregiver assistance to complete basic tasks. Many gave up entirely. Images lacked alt text, excluding screen reader users from visual content.

4
Screen reader compatibility issues

Poor semantic HTML structure caused assistive technologies to misread or skip content entirely, making navigation unpredictable.

Key Findings

Based on the research, these are the three main pain points identified across sessions.

1
Low contrast made program content difficult to read.

Gray text (#8A8A8A) on a light gray background (#EEEEEE) produced a contrast ratio of 2.97:1 — well below the WCAG AA minimum of 4.5:1. Users with low vision described the text as invisible and straining. All four audited elements failed.

2
Small text reduced independence.

Font sizes of 9–10px made it impossible for users with low vision to read program details or form fields without assistance. 70% of participants needed help with basic reading tasks. There was no way to resize text within the site.

3
Unclear form labels and missing alternative text.

Labels like "Contact" and "Your question" gave users no guidance. Images across the site had no alt text, making them invisible to screen readers. Participants called the form "a guessing game" and couldn't access image-based content at all.

Recommendations & Solution

Problem Statement

"How might we improve website accessibility so users with visual impairments can read content, navigate pages, and complete tasks without frustration or assistance?"

Based on the research, the following improvements were recommended to address the identified barriers. Each recommendation was validated through usability testing before implementation.

1. Text Resize Feature

Added A / A / A controls letting users adjust font size — eliminating the need to rely on browser zoom.

2. Improved Color Contrast

Updated color from #8A8A8A to #4F4F4F, raising contrast from 2.97:1 to 7.05:1 — exceeding WCAG AA.

3. Clear Labels & Alt Text

Replaced vague labels with specific ones ("First Name," "Phone Number") with helper text. All images updated with descriptive alt text for screen reader users.

Key Learnings

💬

Empathy Over Assumptions

I assumed I understood accessibility needs, but watching users struggle with "simple" tasks taught me to listen first, design second.

🤝

Translate Research to Action

Stakeholders needed business impact, not just user stories. Connecting accessibility to sign-up metrics made the difference.

🔄

Iterate Based on Feedback

Usability testing revealed issues I missed. Embracing that "done" meant iterating until users succeeded, not defending my first solution.

Next Steps

📊 Regular Monitoring

Conduct quarterly accessibility audits to maintain WCAG compliance as the site evolves.

🎯 Expand Accessibility

Address keyboard navigation, focus indicators, and cognitive accessibility.

💬 User Feedback Loop

Implement a mechanism for users to report accessibility issues directly.

👨‍💼 Staff Training

Educate content creators on maintaining accessibility when adding new programs.

🧪 Expanded User Testing

Conduct follow-up research with a larger, more diverse group of users with disabilities to validate improvements.

Project Summary

Through systematic UX research and accessibility audits, I identified critical barriers preventing visually impaired users from accessing NISRA's website independently.

By implementing text resize controls, WCAG-compliant color contrast, and clear form labels, the redesign achieved a 20% increase in program sign-ups, with 80% of users reporting the site was easier to use.

Key to success: User-centered research with visually impaired participants revealed specific pain points that informed targeted, measurable accessibility improvements.
